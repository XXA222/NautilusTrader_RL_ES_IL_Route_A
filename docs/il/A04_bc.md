# A-04 BC baseline implementation

A-04 adds a Train-inner adapter around the existing L4 `RLProvider.distill()` / `behavioral_clone()` path. The adapter consumes the recorded expert `Transition.action` target (before risk and execution adjustment), retains every complete episode row, requires a single frozen observation schema and fold, and refuses validation/test data or L4 `VecNormalize`. The existing L2 causal feature scaler remains part of the stored policy observation; no second scaler is fit here.

`train_behavioral_clone()` requires an already-created, pristine L4 provider with zero environment updates. It checks observation width, trains the existing SB3 actor, and reports deterministic action MSE, MAE, direction agreement, deadband and nonzero fractions, action distribution, and target/prediction flip counts. A model predicting only inside the predeclared deadband is explicitly flagged as collapsed-to-flat. `FrozenBCPolicy` adapts a trained deterministic actor to the same native collector protocol for an independent Nautilus rollout. `publish_bc_artifact()` publishes an immutable SB3 checkpoint and provenance sidecar containing the actor mapping, dataset manifest hash, parity and behavior reports, and an explicit no-economic-claim marker.

`evaluate_bc_candidates()` implements the RFC's finite Train-inner candidate recipe: epochs `[10, 30, 60]`, learning rates `[0.0001, 0.0003]`, batch size `256`, seeds `[11, 23, 37]`, and action validation tolerance `0.001`. Before the first optimizer update it immutably records a selection plan with the dataset-manifest hash, L4 recipe, fit/selection time windows, bounded candidate grid and selection rule; the winning actor sidecar binds that plan by SHA-256. It fits only on episodes ending before a caller-frozen Train-inner selection interval, verifies that selection episodes fall inside that interval, and requires fit/selection data to share their native source/schema identities without sharing market windows. It checks the dataset manifest's source, fold, schema, expert, seed and time coverage. All candidate fit/selection behavior reports are embedded in the immutable winning actor sidecar. Selection is deterministic: minimum reserved-block MAE among non-collapsed candidates, then MSE, then candidate ID. If every actor is flat, it writes a hash-bound FAILED report containing all candidate diagnostics and raises `BCCandidateSweepBlocked`. The selected actor remains a behavioral candidate and must still pass independent native replay/economic gates.

`native_rollout_report()` summarizes full independent native episodes without synthesizing an execution ledger. The collector records the signed post-action exposure from the native account snapshot (including the pre-terminal policy barrier), and the report derives continuous holding runs, zero-position and nonzero-action fractions, target flips, SUBMIT decisions, event-identified native fills, native net return, peak-to-trough drawdown, currency-separated commissions/funding facts, and risk interventions. Terminal settlement fills are included once; SUBMIT remains distinct from fill. For multiple episodes it reports per-episode returns/drawdowns and does not compound across reset accounts. The report is explicitly descriptive and keeps `economic_claim_eligible=false`; A-00 historical rule/fee evidence and the broader economic gates still control strategy claims.

`evaluate_bc_native_rollouts()` is the independent replay entry point. It loads the SB3 actor named by the immutable artifact sidecar, validates the checkpoint and dataset-manifest hashes, requires a Train-inner native environment, matches each rollout's source/fold/config/transition/observation identities to the actor's training manifest, and atomically publishes a non-overwritable report bound to the actor hash, seeds and episode windows. It never reads validation, Test or Holdout data.

## Gate and status

The candidate runner has a synthetic contract test proving fit/selection time separation, frozen dataset-manifest coverage and immutable selected-actor publication. Native report contract coverage uses a real synthetic Nautilus replay and verifies native fill/equity/exposure capture. It does not claim that a historical BC actor has been trained or economically validated. A-00 found no eligible historical rules/fees/margin evidence, so historical net-return and strategy-selection claims remain blocked. To run the real recipe, supply a frozen Train-inner ExpertBC Parquet dataset, matching L4 config/fingerprint, and an environment factory for independent native evaluation. Independent native replay results must report both account facts and the behavior metrics; low MSE alone is not acceptance.

## Fixed first candidates

The RFC recipe is recorded without expanding its search budget: epochs `[10, 30, 60]`, learning rates `[0.0001, 0.0003]`, batch size `256`, seeds `[11, 23, 37]`, and action validation tolerance `0.001`. Candidate selection is restricted to a reserved Train-inner time block; all final native replay uses the same base risk and execution assumptions. This module intentionally leaves scheduling and economic adjudication to the run orchestrator.
